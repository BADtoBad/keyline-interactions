它被称为“自我改进”的智能体，原因并不是它会凭空改变目标，而是把反馈变成可检查的改进。

闭环实战：Warp 的 Issue 分流智能体

Warp 的 Issue 分流智能体 展示了这套自我改进 Skill 框架。Issue 被提交时，会启动一个智能体，分析它的可行性、分配标签，并建议修复方向。

在一个示例 Issue 中，第一阶段的内部 Skill 整体表现不错，却漏掉了一个标签。该标签表示可以直接由智能体从头到尾修复这个 Issue，无需产品与技术规范。

外部改进器 Skill 作为定时的“更新分派器”运行，拉取刚关闭的 Issue，把内容汇总成一份 JSON 文件，然后重新注入上下文。

接下来，智能体维护者识别出具体反馈信号，然后做出最小修改。它创建了一个修改内部 Skill 的 PR，让缺少明确 UI 或 UX 形态的问题也可以进入下一步。

整套更新只是一个 Skill 文件，可以沿用常规代码评审流程，清楚说明每个修改的依据。
